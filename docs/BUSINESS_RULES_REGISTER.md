# Business Rules Register (BR-01 to BR-12)
**Team ID:** T080 | **Problem Statement:** PS-110  
**Project:** Cloud Kitchen Multi-brand Order Routing and Kitchen Capacity Engine  
**Team Members:** Pavan Neelappa Mirji & Padmavathi B (Section: CSD)

---

| Rule ID | Rule Name | Description & Specification | Edge Cases & Boundaries |
| :--- | :--- | :--- | :--- |
| **BR-01** | Kitchen Eligibility & Routing | A kitchen is eligible for an order if and only if: <br>1. The kitchen serves the brand.<br>2. The kitchen is listed in the delivery zone's eligible kitchen list.<br>3. Operating hours encompass the order placement timestamp.<br>4. The kitchen possesses all required stations for all items in the order.<br>Route to the eligible kitchen with the **lowest projected ready time**. Break ties by: (1) lowest current load, (2) lowest kitchen ID. | Boundary check for operating hours; tie-breaking precedence. |
| **BR-02** | Station Capacity & Batching | Each station has a fixed slot capacity. Each order item occupies 1 slot for its recipe duration. Identical recipes arriving within 3 minutes ($\le 3$ min) may batch into 1 slot up to the recipe's `batch_size`. | **Mandatory Edge Case 1:** Two identical recipe items placed exactly 3 minutes apart must batch together ($\|t_2 - t_1\| \le 3\text{ min}$). |
| **BR-03** | Order Sequencing & RUSH Priority | Default queue ordering is FIFO by order placement time. An order gains RUSH priority if `channelPriority == true` OR `orderValue > 1500`. A RUSH order may jump ahead of up to 3 non-RUSH orders. An individual non-RUSH order cannot be delayed by more than 2 jumps. | **Mandatory Edge Case 2:** RUSH order attempting a 4th jump is capped at 3 jumps and must wait behind the 4th order. |
| **BR-04** | Ready Time & Dependencies | Ready time = $\max(\text{item completion times}) + 3\text{ min packaging}$. Predecessor item dependencies must finish completely before dependent successor items can start ($\text{start}(B) \ge \text{end}(A)$). | Dependent item must wait for both predecessor completion and available station slot. |
| **BR-05** | Promised Time & Late Risk | $\text{Promised Time} = \text{Ready Time} + \text{Zone Delivery Minutes} + 5\text{ min buffer}$, rounded UP to the next 5-minute boundary ($\lceil T / 5 \rceil \times 5$). If projected ready time exceeds order time + 45 minutes ($> 45$), evaluate alternative eligible kitchens; reroute only if alternative saves $\ge 10$ minutes. Otherwise accept with `LATE_RISK`. | **Mandatory Edge Case 3:** Projected ready time exactly 45 minutes does NOT trigger reroute evaluation ($45 \not> 45$). |
| **BR-06** | Load Shedding / Throttling | When projected ready time for a new order exceeds 60 minutes ($> 60$ min from order time), mark the kitchen `THROTTLED`. A throttled kitchen accepts ONLY orders for which it is the sole eligible kitchen. Throttling clears when projected load falls strictly below 40 minutes ($< 40$ min). | **Mandatory Edge Case 4:** Kitchen projected load exactly 60 minutes does NOT trigger throttling ($60 \not> 60$). |
| **BR-07** | Stock-Out & Substitution | If an item is out of stock at a kitchen, query the brand substitution table. Substitute only if $\| \text{price}_{\text{sub}} - \text{price}_{\text{orig}} \| \le \text{₹}20$. If no valid substitute, remove the item and reprice order. If all items are removed, cancel order. | **Mandatory Edge Case 5:** Substitute price exactly ₹20 higher is accepted (boundary is inclusive $\le 20$). |
| **BR-08** | Order Cancellation | Free cancellation before preparation starts on any item. Once preparation starts, charge customer for started items. If aggregator cancels after prep starts, charge channel 100% of started items. At the exact prep-start timestamp, preparation is considered started. | **Mandatory Edge Case 6:** Cancellation timestamp exactly equal to first item prep-start timestamp is considered started (not free). |
| **BR-09** | Channel Economics | **Aggregator A:** 22% commission.<br>**Aggregator B:** 18% commission.<br>**Own App:** 0% commission + ₹15 fixed payment fee.<br>**Packaging Fee:** ₹10 per item, capped at ₹40 per order.<br>**GST:** 5% on gross food value. | **Mandatory Edge Case 7:** Packaging fee cap reached with 5 items ($5 \times 10 = 50 \rightarrow \text{₹}40$). |
| **BR-10** | Late Delivery Penalty | If actual hand-off occurs after promised time ($\Delta = t_{\text{actual}} - t_{\text{promised}} > 0$), charge ₹50 per started 10 minutes of lateness, capped at ₹200. Charged to Brand unless lateness was caused by a `THROTTLED` kitchen routing, in which case charge Kitchen cost centre. | $1\text{ to }10\text{ min} = \text{₹}50$; $11\text{ to }20\text{ min} = \text{₹}100$; $21\text{ to }30\text{ min} = \text{₹}150$; $31+\text{ min} = \text{₹}200$. |
| **BR-11** | Brand-Kitchen Rent | Brand pays kitchen ₹2 per order + 3% of net food value. If a brand completes fewer than 30 orders at a kitchen in a day ($< 30$), apply a ₹500 minimum daily fee. | **Mandatory Edge Case 8:** Brand with exactly 30 orders does not qualify for the minimum fee (normal formula applies). |
| **BR-12** | Rule Execution Precedence | Pipeline order: <br>1. Eligibility $\rightarrow$ 2. Throttling $\rightarrow$ 3. Stock-Out/Substitution (must precede scheduling) $\rightarrow$ 4. Routing by Ready Time $\rightarrow$ 5. Sequencing (RUSH jumps) $\rightarrow$ 6. Station Batching $\rightarrow$ 7. Dependency Scheduling $\rightarrow$ 8. Promised Time. | Strict pipeline ordering ensures deterministic, reproducible scheduling and accounting. |
